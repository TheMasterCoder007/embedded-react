The smallest verified target. The RP2040 has 264 KB of SRAM, no FPU and no external RAM, so this
example uses Flow B: the compiled C app _is_ the firmware. The example project is at
[`examples/rp2040/rp2040-touch-lcd-1.69`](https://github.com/TheMasterCoder007/embedded-react/tree/master/examples/rp2040/rp2040-touch-lcd-1.69)
and builds the watch-face demo: a digital clock with day, date and battery, heart-rate and live
step-counter cards, and a swipe-in bubble level.

**Board:** Waveshare **RP2040-Touch-LCD-1.69**. A 1.69" 240×280 rounded-rectangle **ST7789V2** panel
(portrait, with a 20-row GRAM offset), a **CST816S** capacitive touch controller, a **QMI8658** IMU, 4 MB
flash. The round 1.28" sibling (GC9A01A, 240×240) shares the pins and touch chip; see
[Tuning](#tuning-for-your-board).

```text
App.jsx  →  build --aot  →  app.gen.c  →  C engine  →  pico-spi-lcd backend  →  ST7789V2
                                                                  ↑
                                                           CST816S touch
```

## Build and flash

You need the **Raspberry Pi Pico SDK**, the **Arm GNU toolchain** (`arm-none-eabi-gcc`), CMake and
Ninja or Make. Point the build at the SDK with `PICO_SDK_PATH`, or let it fetch its own copy with
`-DPICO_SDK_FETCH_FROM_GIT=ON`.

**1. Compile the app to C** at the panel's size:

```bash
npx embedded-react build --aot --screen 240x280
```

Inside the repository: `cd bridges/quickjs/js && ER_AOT_SCREEN_W=240 ER_AOT_SCREEN_H=280 npm run aot -- watch-face`.

**2. Build the firmware.**

```bash
cd examples/rp2040/rp2040-touch-lcd-1.69
PICO_SDK_PATH=/path/to/pico-sdk cmake -S . -B build -G Ninja
cmake --build build                                   # → build/embedded-react-watch.uf2
```

**3. Flash it**, either way:

- Hold **BOOT** while plugging in USB; the board mounts as an `RPI-RP2` drive. Copy the `.uf2` onto it.
- `picotool load -f -x build/embedded-react-watch.uf2`, which needs no button if the current firmware
  supports it.

The watch face appears. Walk with the board and STEPS counts up; swipe right-to-left for the bubble
level and tilt the board. The boot log over USB serial:

```text
embedded-react RP2040-Touch-LCD-1.69 host — Flow B (AOT, no QuickJS)
board: ST7789V2 panel up (240x280, SPI 62.5 MHz)
board: CST816 touch ready (chip id 0xB5; ...)
board: QMI8658 IMU ready (addr 0x6B, accel ±4g @125Hz)
AOT app built at 240x280 (no QuickJS)
```

## How it works

- `main.c` boots the panel, touch and IMU, registers the render backend, calls `er_app_build()`
  once, and runs the frame loop: poll touch, poll the IMU and pedometer, `er_commit()`, present,
  tick. `er_app_tick()` advances the app's `setInterval`, which is what moves the clock.
- `board.c` owns the hardware: the ST7789V2 init sequence and windowing on SPI1, a PWM backlight,
  the CST816S on I²C1 and the QMI8658 on the same bus. Touch is **interrupt-gated**: the CST816S
  sleeps when idle and refuses I²C until a touch, so a GPIO edge on its INT line tells the loop when
  a report is waiting.
- **Sensors reach the app through `useHostValue`.** The demo declares
  `const steps = useHostValue(0)` (and `dotx`/`doty` for the level). The compiler lowers each to a
  state field with a generated setter, `er_app_set_steps(int)` and so on, which `main.c` calls when
  the value changes. `pedometer.c` turns accelerometer peaks into steps; the level page maps a
  low-passed gravity vector to the dot. This is the general Flow B way to feed host data into a
  compiled app.
- The swipe pager is a `PanResponder` over a 480-wide track, lowered onto the engine's C gesture
  negotiation, so the drag and the flick arrive with no JavaScript involved.
- The backend, `backends/pico-spi-lcd`, keeps one 240×280 RGB565 framebuffer in SRAM (131 KB) and
  on present streams only the dirty rectangle to the panel.
- `CMakeLists.txt` builds the engine with RAM-tuned `ERUI_*` flags (shadows, gradients and the
  keyboard off; node and vector pools sized to the watch face) so everything fits beside the
  framebuffer in 264 KB. [Memory](../memory.md) has the sizes.

## Tuning for your board

| Symptom                                               | Fix, in `board.c` unless noted                                                                                                     |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Image shifted vertically, a garbage strip at one edge | `LCD_Y_OFFSET`: this panel's 280 rows start at GRAM row 20; a round 240×240 GC9A01A needs 0                                        |
| Photo-negative colours                                | Toggle the `0x21` inversion command in `lcd_init_regs()`                                                                           |
| Red and blue swapped                                  | Flip the RGB/BGR bit in MADCTL (`0x36`: `0x00` ↔ `0x08`)                                                                           |
| Mirrored or rotated                                   | Adjust the MADCTL MX/MY/MV bits in `lcd_init_regs()`                                                                               |
| Touch dead or misplaced                               | Check the CST816S is detected in the boot log; it reports pixel coordinates, no calibration needed                                 |
| Steps never count, or count too easily                | `PEDO_HI`, `PEDO_LO`, `PEDO_MIN_STEP_MS` in `pedometer.c`, watching the `-DER_BOARD_DEBUG=1` heartbeat while walking               |
| Sparkle, tearing, wrong pixels                        | Drop `LCD_SPI_HZ` from 62.5 MHz to 31.25 MHz; not every panel likes the faster clock                                               |
| The round 1.28" GC9A01A board                         | Replace `lcd_init_regs()` with the GC9A01A sequence, set `LCD_Y_OFFSET 0` and `BOARD_LCD_HEIGHT 240`, compile the app at `240x240` |

## Bring-up debugging

`-DER_BOARD_DEBUG=1` waits briefly for a USB host at boot and prints a 1 Hz heartbeat with uptime,
the latest touch poll, the live accelerometer sample and the step count. `-DER_BOARD_DEBUG=2` also
holds a colour-bar test pattern for three seconds at boot: clean red, green, blue and white bands prove
the panel driver end to end, so anything wrong after that is the engine or the app. The default build
compiles all of it out.

## Pinout

| Function            | RP2040 GPIO                    |
| ------------------- | ------------------------------ |
| LCD SCLK / MOSI     | GP10 / GP11 (SPI1)             |
| LCD DC / CS / RST   | GP8 / GP9 / GP13               |
| LCD backlight (PWM) | GP25                           |
| Touch SDA / SCL     | GP6 / GP7 (I²C1)               |
| Touch INT / RST     | GP21 / GP22                    |
| IMU (QMI8658)       | GP6 / GP7 (I²C1, address 0x6B) |
